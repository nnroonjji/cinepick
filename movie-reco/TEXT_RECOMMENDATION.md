# 줄글 추천 실제 서버 연결

2026-11-17 변경: ~~기본 모의 응답~~ → **실제 Supabase HTTP 요청**. `text-reco.js`의 기본 경로는 `/functions/v1/recommend`를 호출합니다. `?textReco=one/error/timeout` 등으로 실제 앱의 응답을 바꿀 수 없습니다. 모의 모델 응답은 자동 테스트 안에만 있습니다.

## 현재 경로

`브라우저 TextReco → Supabase recommend → OpenAI Responses API → 후보·이유 검증 → 카드·회차 재검증`

요청과 응답 형식은 이전과 같습니다.

```js
// 요청
{ text: '사용자 문장', candidates: [{ code: '영화 코드', title: '제목', plot: '줄거리', genre: '장르' }] }
// 응답: 추천 순서 그대로, 최대 세 편
[{ code: '영화 코드', reason: '한 줄 추천 이유' }]
```

`data/config.js`의 프로젝트 URL과 publishable 키가 필요합니다. 키가 없거나 서버가 배포되지 않으면 재시도 안내를 표시합니다. AI 키를 브라우저에 넣지 마십시오. [서버 환경변수·권한·배포 순서·한도](../supabase/README.md)를 확인하십시오.

서버 모델 대기는 15초, 브라우저 요청 대기는 20초입니다. 실패 시 모의 추천으로 대체하지 않습니다. 예산과 남은 회차는 응답이 도착한 후에도 다시 검사합니다. 상영표 전체가 과거이면 사용하는 기존 `STALE` 정책은 유지합니다.

줄글 추천·예약·회차 화면의 예산 시트는 드래그 중 금액만 갱신하고 `change`에서 한 번만 재추천합니다. 요청 취소만으로 이미 시작한 모델 비용을 없앨 수 있다고 가정하지 않습니다.

**추가된 횟수 제한: IP별 직전 60초 5회·한국 날짜별 20회, 전체 한국 날짜별 300회. 서버가 세 가지 429 코드를 반환하면 분당 제한은 잠시 후 재시도, 일일 제한은 한국시간 자정 이후 이용을 안내합니다. 일일 제한에서는 즉시 재시도 버튼을 숨깁니다. 카드 이동은 추가 요청이 아닙니다. [공유 DB 예약·배포 전제](../supabase/RATE_LIMITS.md)를 확인하십시오.**

## 로컬에서 확인

저장소 루트에서 실행합니다.

```powershell
python -m http.server 8000 --bind 127.0.0.1 --directory movie-reco
```

`http://127.0.0.1:8000/?now=2026-11-14T10:00`을 엽니다. 현재 저장소 상영표에 맞춰 시간을 고정한 주소입니다. 상영표가 갱신되면 데이터에 포함된 날짜로 바꾸십시오.

1. `로그인 없이 시작` → MBTI 선택 → 선호 영화 두 편 선택 → 예산 10,000원 → 추천 받기 → 오른쪽 위 홈 버튼으로 이동합니다.
2. 홈에서 문장을 입력하고 제출합니다. 대기 표시 후 최대 세 편이 표시됩니다. 다음·이전 버튼으로 순서와 이유를 확인합니다.
3. 카드의 아래 표를 누르면 같은 영화·가격·회차로 예약 화면이 열립니다. `다른 회차 보기`에서 회차를 바꾼 뒤 돌아와도 선택이 유지됩니다.

| 확인할 상태 | 재현 방법 | 기대 동작 |
| --- | --- | --- |
| 정상 | 위 기본 주소에서 제출 | 약 700ms 대기 → 최대 세 편, 응답 순서·이유 표시 |
| 한 편 / 두 편 | 주소에 `&textReco=one` / `&textReco=two` 추가 후 다시 시작 | 실제 반환된 수만 표시하고 다음은 마지막 장 |
| 후보 없음 | 할인 없이 홈의 `예산으로 고르기`에서 5,000원으로 낮춘 뒤 홈으로 돌아와 제출 | 카드·카드 탐색을 감추고 예산 변경 안내 |
| 빈 결과에서 복구 | `예산 바꾸기`로 10,000원 선택 | 새 조건으로 요청하여 결과 표시 |
| 요청 실패 | 주소에 `&textReco=error` 추가 후 다시 시작·제출 | 오류 안내와 `다시 시도하기` 버튼 |
| 시간 초과 | 주소에 `&textReco=timeout` 추가 후 다시 시작·제출 | 8초 뒤 시간 초과 안내와 재시도 버튼 |
| 요청 중 이탈 | 제출 직후 홈 버튼, 다른 문장으로 다시 제출 | 이전 요청 취소, 새 응답만 표시 |
| 맞춤 추천 회귀 | 홈의 추천 포스터 카드 선택 | 기존 MBTI·선호 영화 기반 맞춤 추천 |

`error`/`timeout` 주소에서는 재시도도 같은 오류를 재현합니다. 정상으로 복구하려면 해당 파라미터를 제거한 주소를 열어 다시 제출합니다. 요청 실패 후 성공하는 재시도는 Node 테스트에서도 검증합니다.

줄글 추천의 상세 화면에서 예산을 조절할 때는 드래그 중 시트를 유지하고, 손을 놓아 값 변경이 끝나면 추천 화면으로 돌아가 새 예산으로 추천합니다. 맞춤 추천의 기존 회차 화면 동작은 유지합니다.

## 다음 단계의 교체 위치

`text-reco.js`의 `mockRequest(payload, {signal})`을 서버 요청으로 교체합니다.

```js
// 요청: 예산·회차 조건을 통과한 후보만 포함
{ text: '사용자 문장', candidates: [{ code: '영화 코드', title: '제목', plot: '줄거리', genre: '장르' }] }
// 응답: 추천 순서 그대로
[{ code: '영화 코드', reason: '한 줄 추천 이유' }]
```

요청 수명·시간 초과·응답 검증은 `TextReco.create()`가 담당합니다. `results(state)`는 현재 예산·할인·남은 회차로 다시 검사하고, `recommend(state, 'text')`는 결과가 없으면 `null`을 반환합니다. 맞춤 추천의 `anyLeft()` 경로는 그대로입니다. 서버 연결 시에는 모델 키를 브라우저에 넣지 않고 서버 측 입력 제한도 추가해야 합니다.

상영표가 전부 과거이면 과거 회차를 다시 사용하는 기존 `STALE` 정책은 이번 범위에서 변경하지 않았습니다. 실시간 운영 보장은 후속 상영표 정책 검토가 필요합니다.
